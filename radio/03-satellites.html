3. Satellites: predict passes, record automatically and analyze

Which satellites can be received (2026)

Satellite Frequency Signal Notes
Meteor M2-3 137.900 MHz (backup 137.100) Digital LRPT, ~120 kHz Weather images. The best target
Meteor M2-4 137.900 MHz (backup 137.100) Digital LRPT, ~120 kHz Same as M2-3
ISS 145.800 MHz (voice/SSTV), 145.825 (APRS) FM Voice and SSTV are occasional
NOAA 15/18/19 137 MHz APT Shut down in 2025. No longer transmitting

LRPT does not sound like voice: it is a constant hiss. In SDR#/SDR++ it shows up as a flat block about 120 kHz wide that appears during the pass (about 10 minutes).

Step 1: find out when they pass

python tools/pasos.py 24 20
  • Arguments: the next 24 hours and a maximum elevation of at least 20°. With no arguments it uses 24 h and 20°.
  • Orbital data: it downloads up-to-date TLEs from Celestrak, computes the passes for Santiago (−33.45, −70.66) and shows Chile time (UTC−3).
  • Which passes to pick: 40° of elevation or more. Below 20° the signal is weak and buildings get in the way.

Sample output:

Satélite      Inicio              Máx Fin    Frecuencia
METEOR-M2 3   Fri 02 22:56:46    70°  23:07  137.900 MHz LRPT

The columns are satellite, start, maximum elevation, end and frequency.

Step 2: prepare the antenna

  1. Use the large elements of the dipole, extended to about 53.4 cm each (including the ~2 cm inside the base).
  2. Open them into a V at about 120° and keep them horizontal, parallel to the ground.
  3. Place it outdoors or in a window with plenty of open sky, away from the PC, using the 3 m cable.
  4. Point the arms east–west, with the opening of the V facing north or south. A horizontal dipole picks up little off the tips of its arms, and in a polar pass the low parts, where the signal is weakest, arrive from the north and the south. This way they hit the antenna broadside. At the top of the pass, the dipole picks up well in any orientation.

Step 3: schedule the automatic recording

In PowerShell, from the project folder. Start 1–2 minutes before the start time given by pasos.py, and compute the duration as (end − start) + 3 min:

.\tools\programar_paso.ps1 -Nombre meteor-m2-3 -Inicio '2026-10-02 22:55' -Minutos 14

It creates a Windows task under Task Scheduler → Library → RTL-SDR. At the scheduled time it:

  1. Closes SDR#/SDR++ if they are open, normally, without forcing them.
  2. Keeps Windows from going to sleep while recording.
  3. Records raw IQ with rtl_sdr through tools\capturar_iq.py: centered at 137.5 MHz, 2.048 MS/s, gain 38.6 dB. The -n option of rtl_sdr is not used, because it never finishes on recordings longer than ~8.7 min; the script copies the exact number of bytes from a pipe. That span covers 137.1 and 137.9 MHz at once, so it works even if the satellite switches frequency. It takes about 0.25 GB per minute (~3.4 GB in 14 min).
  4. Analyzes the recording (step 4) and writes a log.
  5. If the recording is at 137 MHz, extracts the 137.9 MHz channel and decodes it with SatDump (step 5) through tools\decodificar_paso.ps1. The images end up in grabaciones\<base>_satdump\MSU-MR\.

Useful commands:

.\tools\programar_paso.ps1 -Listar

.\tools\programar_paso.ps1 -Borrar 'meteor-m2-3 20261002-2255'

Extra options: -Frecuencia 145.8e6 (for the ISS, for example) and -Ganancia 29.7.

For the task to work:

  • The PC must be plugged in. On mains power, Windows does not sleep and can wake up for the task. On battery it sleeps after 10 minutes and does not wake up.
  • You must be signed in. The session can be locked, but not signed out.
  • The dongle and the antenna must be connected.

Recording manually, without a scheduled task

.\tools\grabar_paso.ps1 -Nombre meteor-m2-3 -Minutos 14

Step 4: check the result

Everything goes into grabaciones\:

File Contents
AAAAMMDD_HHMM_meteor-m2-3_137500000Hz_2048000sps.cu8 Raw IQ (unsigned 8-bit)
...log What happened during the recording
...png Full waterfall + zoom on 137.1 and 137.9 MHz

In the log and in the PNG you will see something like:

  137.100 MHz: máx +0.4 dB, 0.0 min > +3 dB -> sin señal clara
  137.900 MHz: máx +9.8 dB, 7.5 min > +3 dB -> SEÑAL DETECTADA

That is: no clear signal on 137.1 MHz, and a signal detected on 137.9 MHz for 7.5 minutes. If the signal was caught, the zoom shows a wide band (about 120 kHz) that lights up for several minutes and drifts slightly because of the Doppler effect.

To analyze a recording again by hand:

python tools/analizar_iq.py grabaciones/ARCHIVO.cu8 --centro 137.5e6 --sr 2048000

Step 4b (optional): review the recording in an SDR program

Convert the recording, or part of it, to an IQ WAV file:

python tools/cu8_a_wav.py grabaciones/ARCHIVO.cu8 --desde 0 --hasta 15
  • What it creates: grabaciones/SDRSharp_AAAAMMDD_HHMMSSZ_<freq>Hz_IQ.wav. The name follows the SDR# format, with the start time in UTC.
  • The limit: a WAV file cannot exceed 4 GB, which at 2.048 MS/s is ~17 minutes. That is why --desde and --hasta (minutes from the start) select the segment.
  • How to open it in SDR#: Source → IQ File (*.wav) → choose the file → Play. It plays back as if it were live. If SDR# does not show the real frequency, set the center by hand (137.5 MHz).

Step 5: get the image with SatDump

SatDump 1.2.2 (portable version) is in satdump\. It was downloaded from github.com/SatDump/SatDump/releases and the zip was kept in downloads\. No installation needed.

Automatic: since 2026-10-20, grabar_paso.ps1 (and so the scheduled task) runs 5.1 and 5.2 by itself after a 137 MHz recording, through tools\decodificar_paso.ps1. If the 72k pipeline does not sync (a 0-byte .cadu), it retries with the 80k one in <base>_satdump_80k\. To run it by hand on an existing recording:

.\tools\decodificar_paso.ps1 -Archivo grabaciones\ARCHIVO.cu8

With -Extraer 137.1e6 it uses the backup frequency. The next steps explain what it does inside.

5.1 Extract the satellite channel

The recording covers 2 MHz centered at 137.5 MHz, and the Meteor is 400 kHz higher, at 137.9 MHz. SatDump expects the signal centered, so it is first shifted to 0 Hz, filtered and decimated to 512 kS/s:

python tools/analizar_iq.py grabaciones/ARCHIVO.cu8 --centro 137.5e6 --sr 2048000 --extraer 137.9e6
  • What it creates: the usual waterfall and ARCHIVO_137.900MHz_512k.cs16, in 16-bit IQ format, a quarter of the original size.
  • Check the verdict before going on: if it says "sin señal clara" (no clear signal) on 137.9, SatDump will most likely get nothing. If the satellite used the backup frequency, repeat with --extraer 137.1e6.

5.2 Decode from the command line

satdump/satdump.exe meteor_m2-x_lrpt baseband grabaciones/ARCHIVO_137.900MHz_512k.cs16 grabaciones/ARCHIVO_satdump --samplerate 512000 --baseband_format cs16
  • meteor_m2-x_lrpt is the normal mode for Meteor M2-3 and M2-4 (LRPT 72k, OQPSK). If it does not decode, try meteor_m2-x_lrpt_80k.
  • While running, it shows the demodulator status. SYNCED and a low "Viterbi BER" mean it is reading data. If it only says NOSYNC, the signal is not strong enough.
  • The images end up in grabaciones/ARCHIVO_satdump/MSU-MR/.

5.2 (alternative) Decode with the graphical interface

  1. Open satdump\satdump-ui.exe → Offline processing tab.
  2. Pipeline: METEOR M2-x LRPT 72k.
  3. Input level: baseband. Baseband format: cs16. Samplerate: 512000.
  4. Input file: the .cs16. Output directory: a new folder.
  5. Click Start. The constellations and the sync status are shown live.

5.3 Which images you get

The Meteor's MSU-MR sends 3 channels over LRPT. By day they are usually 2 visible and 1 infrared, and at night only infrared.

The names in this table are indicative and will be confirmed with the first successful decode. When there is no sync, SatDump finishes without an error but leaves meteor_m2-x_lrpt.cadu at 0 bytes and MSU-MR/ with only product.cbor, without any PNG.

File What it is
MSU-MR-1.png, -2, -3... Each channel separately, in black and white
rgb_MSU-MR_221_False_Color.png or similar Color composite. Only produced with visible channels, that is, by day
..._Thermal_Infrared.png Thermal infrared, with clouds in white. Produced by day and at night
..._projected.png (if present) The image projected onto a map

The image is a strip ~2,800 km wide along the satellite's ground track. Its length depends on how many minutes sync was held: a 40° pass gives about 7–8 useful minutes, and a pass of 70° or more gives about 10–12.

If the image has black lines from signal dropouts, add --fill_missing to the command-line command.

Common problems

Symptom Likely cause / fix
The log says usb_open error -3 SDR#/SDR++ was still open. Close it before the pass
No recording was created The PC was asleep or on battery. Check Task Scheduler → RTL-SDR → History
"sin señal clara" (no clear signal) on both frequencies Antenna blocked or vertical, low pass (< 30°), or the satellite was off. Try a higher pass
Stripes or steps across the whole waterfall Overload from strong FM. Schedule with -Ganancia 29.7
